The optimal way to solve is question is to use the <ConceptModal content={<RunnerTechnique />}>runner technique</ConceptModal>.

Since we want to delete the kth node from the end of the linked list, we can use 2 pointers to track our position.
To remove the kth node, we actually want our pointer to stop our `follow` pointer one node before the one we want to delete.
Then we <ConceptModal content={<DeleteNode />}>delete the node</ConceptModal> by pointing its `next` to the node after the kth one.

To get the `lead` and `follow` pointer positioned correctly,
we start by iterating the `lead` node from 0 to k nodes into the linked list.
With zero-based indexing, this will actually be `k + 1` total steps.

Once the runner is in its starting spot, iterate both the `lead` and `follow` pointers forward simultaneously by one node until `lead.next` is <Null />.
Now our `lead` is at `k = 0`, our `follow` is at `k + 1`, and the node we want to delete is `k`.
We can remove the node and then return the head of our list.

The solution should also account for all the possible scenarios and edge cases since the only constraint the prompt puts on our `k` value is that `k >= 0`.
These cases include:

1. `k == 0` where we delete the tail
2. `k > 0 && k < linkedList.length - 1` where we delete a node inside the list
3. `k == linkedList.length - 1` where we delete the head
4. `k >= linkedList.length` where the item isn't in the list

It's easy to get an off-by-one error, so make sure you understand the indexes we're using in the solution and the cases we're guarding against.
