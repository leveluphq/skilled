The key to this question is getting the data sorted by start time so we can get the meetings in the order they occur throughout the day
which allows us to easily and effectively compare meeting times to merge intervals.

Once sorted, we iterate through our array of meeting times.

1. Track the current combined interval's start and end time.
2. If an item's start time is less than or equal `<=` to the interval's end time, we know they overlap because the meeting starts before the prior combined interval block ends.
3. We also need to track the end time for an interval.
  If a newly added meeting ends later than what the merged interval has stored, we update the end time.
4. If an item isn't merged (it's start time comes after the combined interval's end time), we know that no more meetings should be included in this combined interval because all meetings will start after it ends since our data is sorted.
  So we add the current meeting as the last item in the combined interval output, and it becomes the latest interval that we consider on the next iteration.
