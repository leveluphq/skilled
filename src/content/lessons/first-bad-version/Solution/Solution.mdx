This question utilizes an interesting twist on a binary search question.
Instead of being given an ordered list of numbers,
we're given the total number of code versions,
and we can infer that it is ordered with all the working versions at the front and then all the broken versions at the end coming after the first bad commit is added.

We will perform binary search on the data, and we will move either left or right based on whether the midpoint item is working or broken.

1. Find the midpoint between version 1 and the final version number
2. Use the <IsBadVersion /> function to determine if it is a good/bad commit
3. If the version is working, move the lower bound up, and if it is broken, move the upper bound down
4. Since there are multiple bad versions, we must do this until the lower bound and upper bound to converge to the midpoint to ensure we find the first broken version
