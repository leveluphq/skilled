The same algorithm can need different collection and text choices in different programming languages. A map lookup may return an optional value, insert a default, throw for a missing key, or require a separate presence flag. A queue can be a standard deque or a small wrapper that avoids repeated array shifts.

Use this reference when moving an interview solution between languages. The tables identify operation families and their caveats; the linked preparation guides contain complete examples and language-specific details. These are programming-language comparisons, while the explanations remain in English.

## Decide whether a copy owns independent storage

JavaScript and TypeScript array spreads copy the outer array while retaining references to nested objects. Python list copies have the same shallow-copy concern. Java and C# collection copies retain references to reference-type elements unless the code copies those elements too.

A Go slice assignment shares its backing array. A fresh allocation and copy can separate the outer element storage, but nested slices or pointers still need their own ownership decision. C++ value copies and Rust clones follow the copied types' semantics rather than one universal deep-copy rule.

Swift collection value semantics preserve logical value independence, with implementation details such as copy-on-write affecting when storage is physically duplicated. Kotlin read-only collection interfaces limit the operations exposed through that reference; they do not prove that no other alias can mutate the underlying collection.

Test the actual promise. If a grid algorithm preserves input, mutate or traverse a nested row and compare the caller's grid afterward. A copied-looking expression is not evidence of deep independence. If mutation is intentional, state that boundary in the function contract and avoid presenting the routine as a preserving alternative.

## Treat numeric representation as an algorithm assumption

JavaScript and TypeScript commonly use Number, whose exact integer range is bounded. Python integers grow as needed, but arithmetic cost grows with operand size. Java, C#, Kotlin, Go, C++, Swift, and Rust commonly use fixed-width integer types with language- and mode-specific overflow behavior.

A complement can be outside the supported integer range even when both operands are individually valid. A comparator that subtracts priorities can overflow. A product can exceed a narrow type after only a few multiplications. Choose widened arithmetic, checked operations, a restricted domain, or a different representation deliberately.

Do not translate an overflow-dependent trick between languages by matching type names. State the mathematical operation and the supported domain first. The [complexity reference](/reference/data-structure-time-complexity) and language guides qualify fixed-cost assumptions where they affect an implementation.

## Name the text unit before indexing

JavaScript, TypeScript, Java, C#, and Kotlin/JVM commonly expose UTF-16 code units through basic string indexing or length operations. Go strings hold bytes and range iteration decodes runes. Rust strings are UTF-8 and do not provide arbitrary integer character indexing. C++ string bytes do not automatically decode Unicode.

Python string iteration works with Unicode code points. Swift's Character iteration groups extended grapheme clusters. None of these units can be substituted blindly for every problem's meaning of character. A supplementary emoji and a combining sequence expose different boundaries.

A bracket matcher with a fixed ASCII alphabet can recognize those delimiters through an appropriate byte, code-unit, or scalar view while ignoring ordinary text. A user-visible cursor position or displayed-character count needs a different contract. Include the unit in the output definition before selecting an API.
