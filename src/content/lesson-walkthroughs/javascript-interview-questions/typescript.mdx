## Read closures as access to bindings

The first loop creates callbacks with a function-scoped `var index`. After the loop ends, that one binding contains 3. Calling any of the saved callbacks reads it then, so the results are `[3, 3, 3]`. The functions did not each capture a frozen copy of the number that happened to be present when they were created.

The second loop uses `let position` in the loop header. Each iteration has its own binding, producing `[0, 1, 2]` when the saved callbacks run. No timer is needed to demonstrate the distinction: saving callbacks and invoking them later already separates creation from observation.

When a question includes asynchronous scheduling, first work out which binding is read. Then work out when it is read. Mixing those two questions makes an ordinary closure error look like a timer problem. ## Trace shared objects and reassigned variables

The quiz starts with two variables referring to one object. Mutating the object's count through the alias changes the value visible through the original reference. Reassigning the alias to a second object changes only that variable. The final counts are 2 for the original object and 9 for the new object.

Draw one box and two arrows before the mutation, then add the second box when reassignment occurs. This also explains why two equal-looking object literals are not equal by reference identity. A shallow copy creates a new outer object but can still share nested objects, so a single spread operation does not establish a deep ownership boundary.

## Explain equality using the operation being called

The quiz constructs NaN by converting a nonnumeric string. Strict equality reports that this value is not equal to itself; Object.is reports that the two NaN values are the same value. Those results follow different comparison algorithms. Object.is also distinguishes positive and negative zero, which strict equality treats as equal.

Do not generalize from one operator to every collection operation. A map lookup, an includes check, and an object reference comparison have their own specified equality behavior. If a question asks why a deletion failed, inspect the actual key or callback identity passed to that API. A newly created function with the same body is still a different function object.

## Add receiver and scheduling questions separately

For a method call, identify the receiver supplied by the call expression. Detaching a regular method from its object can lose that receiver. Binding the method or calling it through a closure can preserve it. An arrow uses lexical this, so replacing every function with an arrow is not a universal repair.

For scheduling questions, list synchronous statements first and then identify microtasks and timer tasks. Native promise reactions use microtasks. A teaching class that schedules callbacks with setTimeout has different ordering. The [event-loop guide](/guides/javascript-event-loop) supplies a trace for comparing those queues.

## TypeScript example and implementation choices

The annotations describe object shape and callback return values without changing the quiz's runtime behavior. TypeScript permits the deliberate var loop, so correct types do not imply correct closure intent. Number('not a number') produces a runtime NaN for the equality comparison. The function returns an inferred object shape whose arrays and Boolean fields can be checked just as in JavaScript.

### Worked example

```typescript
function scopeIdentityQuiz() {
  const shared: { count: number } = { count: 1 };
  let alias = shared;
  alias.count = 2;
  alias = { count: 9 };

  const functionScoped: Array<() => number> = [];
  const blockScoped: Array<() => number> = [];
  for (var index = 0; index < 3; index++) functionScoped.push(() => index);
  for (let position = 0; position < 3; position++) blockScoped.push(() => position);

  const invalid = Number('not a number');
  return {
    originalCount: shared.count,
    reboundCount: alias.count,
    varResults: functionScoped.map(read => read()),
    letResults: blockScoped.map(read => read()),
    nanEqualsItself: invalid === invalid,
    nanSameValue: Object.is(invalid, invalid),
    distinctObjectsEqual: shared === alias,
  };
}
```
